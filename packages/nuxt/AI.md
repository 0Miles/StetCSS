# @stet-css/nuxt

Owns the Nuxt module: it registers `@stet-css/vite` with its default static output in every Nuxt build (SSR, `nuxt generate`, `ssr: false`), with the Nuxt project root as the plugin chain's project root.

## Boundaries

- Static CSS, the class set and option defaults live in `@stet-css/vite` and `@stet-css/stylesheet`; `ModuleOptions` passes `scanner` through and nothing else.
- Vue SFC extraction lives in `@stet-css/source`, reached through scanner auto adapters.
- The module injects no runtime, writes no assets and adds no Nitro server code. A project that wants the runtime imports it itself (#14).

## Risks

- **Project root**: Nuxt sets Vite's root to `srcDir` (`app/`). `withProjectRoot` in `src/module.ts` hands every plugin's `configResolved` a config whose `root` is `nuxt.options.rootDir`, so the class set reads `layers/`, `server/` and the rest of the project. It relies on the Vite plugin reading its project root from `config.root` in `configResolved`; a Vite plugin hook that reads the root elsewhere bypasses it. Layers outside the project root (`extends: ['../base']`, npm layers) are not read; add them with `@source`.
- **Nuxt build options** change only when static output requires it: `features.inlineStyles` is turned off because Nuxt cannot inline generated static CSS during SSR.

## Validation

Fixture apps in `tests/fixtures/` driven by `tests/*.test.ts`: `static` (SSR build, server component, `layers/` component) is built by `static.test.ts` and generated by `generate.test.ts`; `spa` (`ssr: false`) by `spa.test.ts`.
