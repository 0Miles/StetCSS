# @stet-css/compiler

The CSS source compiler: parses StetCSS directives and native CSS, resolves the CSS **import graph** (`compileCSSFile()`), and lowers CSS-first authoring into `StetCSSManifest` values, returning native CSS with consumed directives removed plus dependency paths.

## Boundaries

- Entry discovery: `@stet-css/project` decides which files are project entries; the compiler compiles the entries it is given (`compileProjectManifest()`).
- Class usage: the compiler reads only the CSS import graph; finding used classes in source files is `@stet-css/scanner`.
- Native declaration validity: the compiler owns the one `css-tree` check of native `property: value` declarations, public as `@stet-css/compiler/native-declaration` (`checkNativePropertyName`, `matchNativeDeclarationValue`, `cssTreeNativeDeclarationMatcher`, `cssTreeSyntaxError`). Class and at-rule validity around it is `@stet-css/validator`.

## Risks

- **Entry marker**: `@import "@stet-css/core"` is the only user project entry marker. Every `@master` at-rule that starts a statement (`@master entry;`, `@master { … }`, at any depth) fails with the replacement. `assertNoMasterAtRules` decides: the CSS import-graph reader runs it on every stylesheet it reads and `compileCSS` on its own input, both with a source reference for the editor. Routing filters upstream (local-style directive names, the Next Turbopack content condition, project discovery) are deliberately wider and only send files here.
- **Definitions emit nothing alone**: components, utilities, variables, variants, and animations produce CSS only once a class uses or extracts them.
- **Managed vs native**: generated definitions go through managed directives. Native `@layer` blocks are not compiler-managed, and top-level native `@keyframes` stay native CSS; managed animations go inside top-level `@theme`.
- **Directive shape**: managed definition directives (`@defaults`, `@components`, `@utilities`) take bare first-level names such as `btn { }`, with selector states and descendants as nested selectors inside the named block. `@compose` works in managed class definitions and native style rules, including inside `@variant`.
- **Directive syntax changes** carry compiler tests, plus matching updates to `@stet-css/language` tokens (`syntaxes/stet-css.tmLanguage.json`, `src/semantic/css/`) and to the directive list in this package's `README.md` wherever they cover the changed syntax.
- **Import conditions** (`src/css-import-conditions.ts`): an inlined relative `@import` keeps its `layer()`, `supports()` and media conditions as wrapping blocks. Top-level directives (`TOP_LEVEL_CSS_DIRECTIVE_NAMES`, shared with `compileCSS`'s top-level check) stay outside them, and so do the stylesheet's kept `@import` statements, which take on the outer conditions or fail where one import cannot express both. Kept imports then move to the start of the expanded graph with the unconditioned `@layer` statements written before them, so each layer is declared once and in written order. `@stet-css/stylesheet` expands its import graph and builds integration host sources through the same functions, so a change here changes every path's CSS output.
- **Nesting-depth prescan** (`src/css-nesting.ts`): every stylesheet passes `assertCSSNestingDepth` before lightningcss parses it, in `compileCSS` (which also covers `compileCSSManifest(source)` and the browser entry) and in `findCSSImportStatements` (which names each imported file); keep both. lightningcss recurses per nested rule, selector function and media-query parenthesis and kills the process on deep input. The 64-level limit compiles every measured shape on a 0.5 MB worker stack, where 128 nested `:is()` already crash; real stylesheets nest at most about 12. The scanner must tokenize like CSS (matching closers only, opaque unquoted `url(...)`, strings, comments, escapes): anything it counts short lets a crashing stylesheet through. Rerun the nesting tests in `tests/import-graph-inputs.test.ts` after changing the scanner or the limit, or upgrading lightningcss.
- **Native declaration check** (`src/native-declaration.ts`, public as `@stet-css/compiler/native-declaration`): the single `css-tree` check of native `property: value` declarations. `@compose` lowering uses it here; `@stet-css/validator` re-exports it for every build, lint and editor instance and for `validateCSS`. Changing it is a CSS output change everywhere. It keeps no imports beyond `css-tree` and engine types, so the validator loads it without lightningcss. Exceptions for syntax `css-tree` rejects stay narrow (one construct, spec grammar, rewritten into syntax `css-tree` already judges in the same position) with accepting and rejecting rows in `tests/native-declaration.test.ts`.
- **Reference cache** (#202): `compileCSSReferences` reuses a compiled `@reference` tree per base manifest (by identity), root and referenced files while every file it read keeps its stamp (`src/file-stamps.ts`), so CSS modules referencing the same entry share one compile. Warnings of a reused result reach `onWarning` again; compiles with `diagnostics` skip the cache. Cached contexts are shared, so lowering must never mutate a resolution manifest. `createFileStampCache` is public for the project and stylesheet caches.
- **Retired pipelines**: build on the CSS-first directive pipeline; old JS `Config` behaviour and PostCSS stay out.
