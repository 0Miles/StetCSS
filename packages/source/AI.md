# @stet-css/source

Owns **candidate extraction**: pulling unvalidated, class-like strings out of raw source text, plus the format-aware source adapters (HTML, OXC for JS/TS, Astro, Svelte, Vue) and the order they are tried in (`resolveSourceAdapter`, `extractSourceClassCandidates`), shared by the scanner and the stylesheet's project class set.

## Boundaries

- Candidate validation and rule insertion: `@stet-css/scanner` (through `@stet-css/validator`) for text a caller supplies, rendering in `@stet-css/stylesheet` for project files; source returns strings only.
- Lexical primitives (source ranges, class-list tokenizing, unit constants): `@stet-css/lexer`.

## Risks

- **Candidates are CSS output**: an extra candidate adds rules and a missed one drops required CSS, so treat a change in what an adapter extracts as a CSS output change.
- **Static strings only**: OXC extraction reads string literals and expression-free template literals; treat concatenated or interpolated class names as not statically knowable.
- **Template placeholders in text extraction**: `extractClassCandidates` replaces each closed `${…}` with the string literals its expression holds and drops the class fragments touching it (`grid-` in `grid-${size}`), so placeholder code and fragments of runtime-only classes are never candidates (`src/template-placeholders.ts`). A fragment runs to ASCII whitespace or a quote; an unclosed `${` stays text.
- **OXC parsing**: JS/TS that OXC fails to parse, or that nests past `exceedsScriptNestingLimit` from `@stet-css/lexer` (deep enough to crash OXC), falls back to `extractClassCandidates` text extraction, so parser differences shift the candidate set. Astro frontmatter parses as a module and keeps its program despite a top-level `return` (oxc's `TS(1108)`), since Astro compiles it into an async render function; any other error still falls back.
- **Parse stack**: sources over 1 KiB parse on a worker thread whose stack grows with the source (`src/adapters/oxc-stack.ts`), because chains the prescan lets through (one level per line, `else if`, `a = b = c`, `new`) still overflow OXC's native stack and kill the process. The call blocks on `Atomics.wait`, and the worker is dropped after 2 s idle. Sources over 1 MiB would need more than the 1 GiB stack cap, so they skip OXC and use text extraction. When the smallest parse thread cannot start, it warns once and parses inline; when only a larger one cannot, that file uses text extraction. The module also runs the `exceedsScriptNestingLimit` prescan. `@stet-css/language` keeps a copy that differs only in `PACKAGE_NAME`, because `packages/language/AI.md` keeps language's imports off source and the dependency would change `bun.lock` (the AGENTS.md dependency chain itself allows it); `packages/language/tests/oxc-stack-copy.test.ts` fails when they drift.
- **Character references**: class attributes are read by the classes the host renders: HTML and Astro static attributes through `decodeStetCSSHTMLAttributeValue`, JSX attribute strings through `decodeStetCSSJSXAttributeString` (oxc keeps them as written), Vue `class` attributes and `:class` bindings through the compiler's decoded values, and Svelte through its compiler. Astro and Vue blank those attributes out of the markup text extraction, so the source spelling is not extracted too. Script text and JavaScript strings stay as written. Candidates split on ASCII whitespace only (`splitASCIIWhitespace` from the lexer), as the DOM splits a class list, so a no-break space joins classes.
- **Adapter matching** keys on the file id and extension, including ids with a `?query` suffix; a wrong match routes the file to the wrong extractor.
- **Optional peers**: when `vue` or `svelte` is missing, the adapter warns once per specifier and falls back to text extraction (`src/adapters/optional-peer.ts`).
